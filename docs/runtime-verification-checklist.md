# Runtime verification checklist - required before resume performance claims

No unchecked item below is a successful result. Portable Java/Maven now support compilation, packaging and 141 passing unit tests; Docker-backed verification is still blocked. See [current progress and shell setup](runtime-verification-progress.md). Record date, commit, versions, commands, hardware/workload, exit codes and raw evidence. Stop and fix failures before collecting benchmark claims. Use disposable local databases; never truncate production data.

1. **Java:** `java -version`. Require a working JDK 21 toolchain; fix PATH/JAVA_HOME before continuing. An absent command or wrong major is a blocker, not a test failure.
2. **Maven:** `mvn -version`. No wrapper is committed; install/configure Maven rather than invoking a nonexistent mvnw. Confirm the JVM Maven uses. Resolve artifact/version/network failures honestly.
3. **Docker:** `docker version` and `docker compose version`. Require a reachable Linux-container daemon and permission to pull postgres:17.6. Missing daemon/image/network access blocks Testcontainers.
4. **PostgreSQL:** `docker compose up -d --wait postgres`. Check container health; do not delete volumes as a troubleshooting shortcut. Compose may read `.env`; export matching DB_URL/DB_USERNAME/DB_PASSWORD into both API and worker shells separately. Existing fallback credentials are local demo values only.
5. **Compile/migrations/startup:** `mvn -B -DskipTests compile`, then `mvn -B -DskipTests package`. Run `java -jar target/durableflow-0.0.1-SNAPSHOT.jar` in one terminal. Inspect startup/Flyway V1-V13 and Hibernate validation; query `/actuator/health` from another terminal. Missing artifacts, migration checksum/schema mismatch or app startup errors must be resolved and recorded, not silently ignored. Check flyway_schema_history with psql using your configured credentials.
6. **Unit tests:** `mvn -B '-Dtest=*Test,!*IntegrationTest' test`. Inspect Surefire XML/text, including new resource/filter checks, evaluation negative cases and telemetry cardinality/failure tests. Confirm executed vs skipped counts; a Maven exit alone does not establish that every intended test was selected.
7. **PostgreSQL integration:** `mvn -B '-Dtest=*IntegrationTest,!BenchmarkIntegrationTest' test`, then `mvn -B test` for the complete default regression selection. Require actual DB containers and no assertion/migration/type errors. Verify the opt-in benchmark is intentionally skipped. Preserve reports before running another command that overwrites them.
8. **Demos:** Run a uniquely identified worker with `java -jar target/durableflow-0.0.1-SNAPSHOT.jar --spring.profiles.active=worker`, then follow [demos.md](demos.md). Verify core run/history, Saga outcome, exact approval wait before refund, retrieval provenance, agent termination and summary. A paused human wait is expected, not success. Avoid mixing legacy synchronous execute with queued runs.
9. **Chaos/evaluation:** `scripts/run-chaos.ps1 -Scenario all` and `mvn -B '-Dtest=GoldenEvalIntegrationTest' test`. If scripts are disabled, use [chaos-matrix.md](chaos-matrix.md)'s direct Maven command. Inspect no duplicate effect, stale owner rejection, overdue timer/early signal/approval semantics, bounded fallback/agent termination and telemetry isolation. Record controlled simulation vs actual OS/process faults separately. Golden results are target/eval-report.json/.md only after execution.
10. **Benchmark smoke/scaling:** First `mvn -B '-Dtest=BenchmarkIntegrationTest' '-Ddurableflow.benchmark=true' '-Dbench.workflows=20' test`; then run the documented start/queue/DAG/timer/signal workloads and 1/4/16-thread comparison. Inspect validity, completed counts/errors, latency sample counts and tails. Repeated warmed representative runs and independent worker processes remain necessary for scaling claims. See [benchmarks.md](benchmarks.md) and [sql-inspection.md](sql-inspection.md).
11. **Record actual results:** Archive logs/Surefire/eval/benchmark artifacts outside target before the next overwrite, with commit/hardware/JVM/PostgreSQL/pool/poller/workload settings. Run planned manual crash and DB restore/PITR/failover drills separately; automated app context restarts are not DB disaster recovery proof. Do not put real prompts/arguments/secrets in public artifacts.
12. **Update claims:** Change [project status](project-status.md), README and resume only for categories actually verified. Explain failures, skips, unknown usage and limitations. Never extrapolate a local no-op SQL result into real AI/payment capacity or universal exactly-once behavior.

Expected categories to record: prerequisite/tooling blocked; dependency resolution failed; compilation/type-check failed; migration/schema failed; assertion failed; selected test skipped; app/demo timeout; chaos invariant violation; benchmark invalid/incomplete; measured success with raw evidence. These are categories, not fabricated outputs. Health/metrics visibility is distinct from operational readiness/HA/authentication.
